# Introduction to Docker

[Docker is an open platform for developing, shipping, and running applications.](https://docs.docker.com/get-started/docker-overview/)

By using Docker we can mitigate the "it works on my machine" problem
-- Docker helps "isolate" applications from the underlying system, making it easier to replicate and run the same application on different environments.


Why not use a VM instead? --- VM is a full-fledged OS with hardware drivers, programs, and applications. It's heavy and slow to start for only one application.

But, provisioned VM (often in cloud environment) can run multiple containerised apps.


# Core concepts

Isolated application with its dependencies and configuration bundled together -- this is a **container**.
* ```docker run ubuntu``` will create a container with Ubuntu OS.
* ```docker ps``` will list all running containers --- get container_id
* ```docker stop <container_id>``` will stop a container.
* ```docker rm -f <container_id>``` will force remove a container (stop -> remove).
* ```docker rm <container_id>``` will remove a container.
* ```docker logs <container_id>``` will show logs of a container.
* ```docker stats``` will show resource usage of containers.

To make container replication easier, we use **images**. An image is a read-only template with instructions for creating a Docker container. 

Images can use other images as a base; each image instruction in a **Dockerfile** is a **layer**, and layers are cached to speed up the build process.

Images can be stored and shared in a **registry**. The default registry is Docker Hub. Other registries: Amazon ECR, Google Container Registry, your own private registry.
* ```docker pull/run/push``` are commands to interact with required images via configured registry.
* ```docker image ls``` will list all images on the system.

The degree of isolation between containers is controlled by **namespaces** and **cgroups**. Namespaces provide isolation for processes, networking, and filesystems, while cgroups manage resource allocation.

Docker objects such as images, containers, networks, and volumes are managed by **Docker daemon** through the Docker API.

# Build Image
* ```docker build -t image-name:v1 .``` will build an image from the Dockerfile in the current directory and tag it as image-name:v1.
* ```docker build -t image-name:v1 -f path/to/Dockerfile .``` will build an image from the specified Dockerfile.
* ```docker build -t image-name:v1 -f path/to/Dockerfile -m 2GB .``` will build an image with a memory limit of 2GB.
* ```docker build -t image-name:v1 --build-arg APP_COLOR=blue .``` will build an image with an argument passed to the Dockerfile.
* ```docker build -t image-name:v1 --no-cache .``` will build an image without using cache.

[Best practices](https://docs.docker.com/build/building/best-practices/)

# Run Container
* ```docker run -d -p 8080:80 docker/welcome-to-docker```
* ```docker run -d -p HOST_PORT:CONTAINER_PORT some_image``` will run a container with  some_image in detached mode, mapping host port to container port.
Now, any traffic sent to HOST_PORT on your machine will be forwarded to CONTAINER_PORT.

* ```docker run -P nginx``` will publish all of the exposed ports configured by the image to random free ports.

Set environment variables with ```-e``` flag:
* ```docker run -e APP_COLOR=blue simple-webapp-color```
* ```docker run -e foo=bar some_image```

Restrict memory and cpu usage with ```--memory``` and ```--cpus``` flags:
* ```docker run --memory="100m" --cpus=1.5 some_image``` will restrict the container to 100MB of memory and 1.5 CPU cores. 
Combine with ```docker stats``` to monitor resource usage.

Default network is bridge network. Use custom network with ```--network``` flag. But first, we need to create it:
* ```docker network create mynet```
* ```docker network ls``` -- verify network creation
* ```docker run -d -e POSTGRES_PASSWORD=secret -p 5433:5432 --network mynet postgres``` -- run container in custom network
* ```docker network inspect mynet``` -- get details of network

1. On a custom network, containers can resolve each other by name or alias.
2. If no ```--network``` specified, new containers connect to default network -> unrelated containers can communicate.

To persist data (generated by and used by container) beyond container lifecycle, use **volumes**. Volumes are directories on the host that are mounted into a container.
* ```docker run -v /path/in/host:/path/in/container some_image``` will mount host directory (create if not exist) to container directory.
* ```docker volume create some_volume``` will create a volume.
* ```docker volume ls``` -- list volumes.
* ```docker volume rm <volume-name-or-id>``` -- remove a volume (only unattached).
* ```docker volume prune``` -- remove all unused volumes.
* [Volume mini-lab](https://docs.docker.com/get-started/docker-concepts/running-containers/persisting-container-data/#try-it-out)

Same volume can be shared between many containers.

To share specific host configs / source code / build artifacts with container, use **bind mounts**. Bind mounts useful when real-time file access and sharing between the host and container are crucial.
* Bind mounts has write access to host FS -> security risk. Mitigate with ```ro``` option of the ```--mount``` flag.
